UNIDAD 1 · BASE CONCEPTUAL · 25–35 min

HTML actual, con criterio

Una página sólida empieza por asignar el trabajo correcto a cada tecnología. El marcado describe; CSS presenta; JavaScript programa el comportamiento.

Objetivos

  • Distinguir HTML, CSS y APIs del navegador.
  • Elegir elementos por su significado.
  • Comprobar una página con el teclado.

Un estándar que evoluciona

HTML se desarrolla como Living Standard. «HTML5» sigue siendo una expresión habitual, pero no designa todas las capacidades actuales del navegador. Aprende elementos y APIs concretas y comprueba su compatibilidad.

El significado antes que la apariencia

main identifica el contenido principal; section agrupa contenido temático, normalmente con un encabezado; article representa una pieza autónoma. Un div es un contenedor genérico. Que dos elementos se vean igual no significa que comuniquen lo mismo.

Accesibilidad desde la estructura

El idioma del documento, los encabezados ordenados, los nombres de controles y el foco visible ayudan a comprender y recorrer una página. Un botón nativo ofrece interacción con teclado; un div con un clic no adquiere automáticamente ese comportamiento.

Distingue los conceptos

Una etiqueta es parte del marcado. Una API es una interfaz de programación. Por ejemplo, canvas crea la superficie; getContext("2d") proporciona las operaciones para dibujar en ella.

Ejemplo HTML

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Mi cuaderno de prácticas</title>
</head>
<body>
  <main>
    <h1>Cuaderno de prácticas</h1>
    <section aria-labelledby="objetivo">
      <h2 id="objetivo">Objetivo de hoy</h2>
      <p>Dar significado al contenido.</p>
      <details>
        <summary>Una pista</summary>
        <p>Elige la etiqueta por su función.</p>
      </details>
    </section>
  </main>
</body>
</html>

Ejemplo JavaScript

// El navegador ofrece la API DOM.
const titulo = document.querySelector("h1");
// textContent inserta texto, sin interpretarlo como HTML.
titulo.textContent = "Mi primera práctica";

El laboratorio ejecuta el HTML editable en una vista aislada. Los ejemplos JavaScript son de lectura.

Errores que conviene evitar

  • Usar h1…h6 solo por su tamaño visual.
  • Elegir section como sustituto universal de div.
  • Afirmar que geolocalización o Web Workers son etiquetas HTML.

Reflexión

Si eliminas todo el CSS, ¿el contenido conserva un orden comprensible?

Práctica: Edita la estructura, observa el significado

Cambia el título y el contenido de la sección. Abre details y recorre el resultado con el teclado.

  1. Añade una segunda sección con su h2.
  2. Incluye una lista de tres objetivos.
  3. Comprueba el orden de encabezados y la interacción con details.

Criterio de logro. Debe quedar un h1 que identifica la página y dos secciones con h2. La lista utiliza ul y li. details se abre con su summary sin JavaScript. El tamaño de un título se cambia con CSS, no alterando su nivel semántico.

Autoevaluación

1. ¿Qué describe mejor a HTML?

  1. Define estructura y significado.
  2. Calcula la ubicación del dispositivo.
  3. Ejecuta tareas en segundo plano.

Respuesta A. HTML es un lenguaje de marcado. La geolocalización y los Workers son APIs que se utilizan con JavaScript.

2. ¿Cuándo elegirías article?

  1. Para cualquier bloque con un borde.
  2. Para una pieza de contenido con sentido autónomo.
  3. Siempre que necesites dos columnas.

Respuesta B. article expresa autonomía del contenido; los bordes y las columnas corresponden a la presentación.

3. ¿Qué ofrece un button nativo?

  1. Una base de semántica e interacción con teclado.
  2. El código del servidor.
  3. Acceso automático a la ubicación.

Respuesta A. El control nativo incorpora semántica, foco y activación. Su acción específica puede requerir JavaScript.

UNIDAD 2 · HTML EN ACCIÓN · 35–45 min

Formularios que orientan

Un formulario útil explica qué necesita, ofrece controles adecuados y ayuda a corregir los errores. La validación del navegador es el primer nivel de ayuda.

Objetivos

  • Relacionar label con su control.
  • Aplicar required, min, max y step.
  • Interpretar validity sin confundir validación con seguridad.

Escoge el tipo de dato

email comprueba una forma de dirección, no que la cuenta exista. date usa un valor normalizado de fecha, aunque el control cambie con el navegador. number expresa cantidades; códigos postales y teléfonos suelen necesitar texto, no operaciones numéricas.

Restricciones declarativas

required pide un valor; min y max acotan números o fechas; step define el incremento admisible. minlength y maxlength restringen la longitud del texto. El navegador expone estados como valueMissing, typeMismatch y rangeOverflow.

Ayuda inmediata, validación completa

checkValidity() devuelve si las restricciones se cumplen y dispara invalid en los controles inválidos; reportValidity() también presenta ayuda al usuario. La validación del cliente se puede eludir: una aplicación real debe validar también en el servidor.

Distingue los conceptos

El control range existe por HTML. Mostrar al instante su valor dentro de output requiere escuchar el evento input con JavaScript. Un correo con formato válido no es una identidad verificada.

Ejemplo HTML

<form id="practica">
  <label for="correo">Correo de prueba</label>
  <input id="correo" name="correo" type="email" required>
  <label for="horas">Horas de estudio</label>
  <input id="horas" name="horas" type="number"
         min="1" max="12" step="1" required>
  <button>Comprobar</button>
</form>
<p id="resultado" role="status"></p>

Ejemplo JavaScript

const formulario = document.querySelector("#practica");
formulario.addEventListener("submit", (evento) => {
  evento.preventDefault(); // Práctica local: no se envía.
  // El navegador comprueba antes del evento submit.
  const datos = new FormData(formulario);
  document.querySelector("#resultado").textContent =
    `Práctica válida: ${datos.get("horas")} horas.`;
});

Prueba valores inventados. La práctica muestra un resumen local y no realiza ninguna petición.

Errores que conviene evitar

  • Usar placeholder como único nombre del campo.
  • Insertar entradas del usuario mediante innerHTML.
  • Considerar la validación del navegador una protección del servidor.

Reflexión

¿Por qué una dirección como persona@example.com puede superar type="email" sin demostrar que existe?

Práctica: Un formulario con un inspector visible

Provoca errores a propósito. Observa cómo cambian las restricciones antes de enviar la práctica.

  1. Introduce un correo sin arroba y 13 horas; intenta validar.
  2. Corrige el correo, prueba 2,5 horas y observa stepMismatch.
  3. Completa los campos pendientes y genera un resumen válido.

Criterio de logro. El correo mal formado produce typeMismatch; 13 supera max y produce rangeOverflow; 2,5 no encaja en step="1" y produce stepMismatch. Una ficha válida usa correo con formato admisible, horas enteras de 1 a 12, fecha, alias de 2 a 24 caracteres y la casilla marcada.

Autoevaluación

1. ¿Qué garantiza type="email"?

  1. Que la cuenta pertenece al estudiante.
  2. Que el valor satisface el formato admitido por el control.
  3. Que el mensaje se entregará.

Respuesta B. El tipo email valida sintaxis, no existencia, propiedad ni entrega.

2. Con min="1", max="12" y step="1", ¿qué ocurre con 2.5?

  1. Se acepta siempre.
  2. Se convierte automáticamente en 3.
  3. No cumple el incremento permitido.

Respuesta C. El valor produce stepMismatch porque no encaja en los pasos enteros a partir del mínimo.

3. En una aplicación real, ¿dónde deben validarse los datos?

  1. Solo en el navegador.
  2. También en el servidor.
  3. Solo con CSS.

Respuesta B. La validación de cliente mejora la experiencia; el servidor debe validar lo que recibe.

UNIDAD 3 · GRÁFICOS · 35–45 min

Dibujar sobre píxeles

Canvas es una superficie de dibujo. Comprende la relación entre tamaño visual, coordenadas y resolución antes de trazar o animar.

Objetivos

  • Diferenciar el elemento canvas de su API 2D.
  • Convertir coordenadas del puntero al lienzo.
  • Iniciar y detener una animación de manera controlada.

Un mapa de píxeles

canvas no convierte cada trazo en un elemento del DOM. getContext("2d") devuelve el contexto de dibujo. Debes proporcionar alternativas textuales o controles accesibles para explicar y operar el contenido. SVG es otra opción cuando necesitas objetos vectoriales con estructura.

Dos tamaños y una escala

width y height definen el mapa de bits; CSS define el tamaño mostrado. Si difieren, el dibujo se escala. En pantallas de alta densidad se puede ajustar el mapa de bits según devicePixelRatio y transformar el contexto para dibujar con unidades CSS. Cambiar width o height borra el lienzo y reinicia su estado.

Eventos y fotogramas

Pointer Events unifica ratón, lápiz y tacto. getBoundingClientRect() permite transformar clientX/clientY a coordenadas locales. requestAnimationFrame() pide un próximo fotograma; no es un bucle automático. Guarda su identificador y usa cancelAnimationFrame() para detenerlo.

Distingue los conceptos

canvas aporta el elemento; la API Canvas 2D dibuja; Pointer Events recibe la interacción; requestAnimationFrame coordina la actualización con el navegador.

Ejemplo HTML

<canvas id="lienzo" width="800" height="300"
        aria-label="Ejemplo: un rectángulo violeta">
  Ejemplo de dibujo: un rectángulo violeta.
</canvas>
<button id="dibujar">Dibujar ejemplo</button>

Ejemplo JavaScript

const lienzo = document.querySelector("#lienzo");
const ctx = lienzo.getContext("2d");
document.querySelector("#dibujar").addEventListener("click", () => {
  if (!ctx) return;
  ctx.clearRect(0, 0, lienzo.width, lienzo.height);
  ctx.fillStyle = "#6658d3";
  ctx.fillRect(60, 50, 200, 100);
});
// Sin transformar el contexto, una coordenada X sería:
// (evento.clientX - rect.left) * lienzo.width / rect.width

El laboratorio ajusta la resolución a la pantalla y conserva los trazos como datos para redibujarlos al cambiar de tamaño.

Errores que conviene evitar

  • Usar coordenadas de la ventana sin restar la posición del lienzo.
  • Cambiar width en cada fotograma y perder todo el contenido.
  • Crear varios bucles de animación o dejar uno activo al salir.

Reflexión

¿Por qué duplicar el ancho CSS de un canvas puede hacer que el dibujo se vea borroso?

Práctica: Un lienzo que responde a diferentes entradas

Dibuja con el puntero, usa flechas y espacio o carga el ejemplo. La animación es opcional y dispone de pausa.

  1. Dibuja con dos colores y dos grosores.
  2. Usa el teclado para mover el cursor y marcar un punto.
  3. Inicia y detén la animación; cambia de unidad y comprueba que se detiene.

Criterio de logro. Los trazos deben seguir al puntero, incluso tras redimensionar. El teclado y el botón de ejemplo ofrecen otras formas de interacción. Solo existe una animación activa; se cancela al pausar, ocultar la pestaña o abandonar la práctica.

Autoevaluación

1. ¿Qué hace getContext("2d")?

  1. Crea una etiqueta SVG.
  2. Obtiene el contexto para dibujar en dos dimensiones.
  3. Descarga una imagen.

Respuesta B. El contexto 2D ofrece métodos como fillRect, lineTo o clearRect.

2. ¿Qué sucede al asignar canvas.width?

  1. Solo cambia CSS.
  2. Se conservan siempre los píxeles.
  3. Se reinicia el mapa de bits y el estado del contexto.

Respuesta C. Redimensionar el mapa de bits borra el dibujo; conserva los datos necesarios para reconstruirlo.

3. ¿Cómo detienes una petición de animación pendiente?

  1. Con cancelAnimationFrame(id).
  2. Ocultando cualquier botón.
  3. Con stopCanvas().

Respuesta A. Guarda el identificador devuelto por requestAnimationFrame y cancélalo explícitamente.

UNIDAD 4 · APIs DEL DISPOSITIVO · 30–40 min

De las coordenadas al mapa

Obtener una posición y representarla en un mapa son dos tareas diferentes. Aquí practicarás ambas, empezando por coordenadas públicas de ejemplo.

Objetivos

  • Interpretar latitud, longitud y precisión.
  • Gestionar permiso y errores de geolocalización.
  • Crear un enlace oficial a Google Maps sin clave API.

¿De dónde sale la posición?

navigator.geolocation solicita la posición al navegador, que se apoya en los servicios del dispositivo y del sistema. Estos pueden combinar GNSS/GPS, redes Wi-Fi y otras señales. La página no calcula por sí misma la posición ni conoce necesariamente qué fuente se utilizó.

Coordenadas y una estimación

La latitud va de −90 a 90 grados; la longitud, de −180 a 180. En el orden latitud,longitud, los valores negativos indican sur y oeste. coords.accuracy expresa una estimación de precisión horizontal en metros, con un nivel de confianza del 95 % según la especificación; no una localización exacta garantizada.

Permiso primero, mapa después

getCurrentPosition necesita un contexto seguro y permiso; también puede fallar por indisponibilidad o tiempo de espera. El navegador puede recurrir a servicios de ubicación en red. El enlace de Google Maps representa las coordenadas elegidas: al abrirlo, se envían a Google. Maps URLs no requiere clave API.

Distingue los conceptos

Geolocation API obtiene la estimación de posición. Google Maps muestra una ubicación. Abrir un mapa no demuestra que esa posición proceda del dispositivo: también puede ser un ejemplo fijo.

Ejemplo HTML

<button id="ubicar">Solicitar ubicación</button>
<p id="estado" role="status"></p>
<a id="mapa" hidden target="_blank"
   rel="noopener noreferrer">Ver en Google Maps</a>

Ejemplo JavaScript

const estado = document.querySelector("#estado");
const mapa = document.querySelector("#mapa");
document.querySelector("#ubicar").addEventListener("click", () => {
  if (!isSecureContext || !("geolocation" in navigator)) {
    estado.textContent = "Geolocalización no disponible en este contexto.";
    return;
  }
  navigator.geolocation.getCurrentPosition(({ coords }) => {
    const punto = `${coords.latitude},${coords.longitude}`;
    mapa.href = "https://www.google.com/maps/search/?api=1&query="
      + encodeURIComponent(punto);
    mapa.hidden = false;
    estado.textContent = `Precisión estimada: ${coords.accuracy} m.`;
  }, (error) => {
    const mensajes = { 1: "Permiso denegado", 2: "Posición no disponible",
                       3: "Tiempo de espera agotado" };
    estado.textContent = mensajes[error.code] || "No se pudo obtener la posición";
  }, { timeout: 10000, maximumAge: 0, enableHighAccuracy: false });
});

El vínculo usa la interfaz oficial Maps URLs. La ubicación real es opcional. Para uso docente estable, sirve el material en HTTPS o localhost; el tratamiento de file:// depende del navegador.

Errores que conviene evitar

  • Confundir permiso denegado con falta de conexión.
  • Presentar las coordenadas como exactas.
  • Solicitar ubicación al cargar la página o guardarla sin necesidad.
  • Confundir enableHighAccuracy con una garantía de uso de GPS.

Reflexión

¿Puedes enseñar el funcionamiento de un mapa sin pedir la ubicación real de ningún estudiante?

Práctica: Visualiza una posición en Google Maps

Elige una ciudad de ejemplo y observa el enlace. Si lo deseas, solicita la ubicación del dispositivo; después decide si abres el mapa.

  1. Selecciona dos ciudades y compara el signo de sus longitudes.
  2. Abre una de las posiciones públicas en Google Maps.
  3. Simula los tres errores y explica qué harías en cada caso.

Criterio de logro. Madrid y Sevilla tienen longitud oeste negativa; Barcelona, este positiva. El enlace cambia el parámetro query con latitud,longitud. Ante permiso denegado se respeta la decisión y se ofrece el ejemplo; ante indisponibilidad se revisan los servicios; ante timeout se puede reintentar. No es necesario usar datos personales.

Autoevaluación

1. ¿Quién proporciona las coordenadas solicitadas por la página?

  1. El elemento HTML map.
  2. El navegador mediante los servicios de ubicación disponibles.
  3. Siempre un cálculo escrito en HTML.

Respuesta B. La API delega en el navegador y en los servicios de ubicación del dispositivo.

2. ¿Qué representa accuracy?

  1. Un zoom de Google Maps.
  2. La distancia hasta Madrid.
  3. Una estimación de precisión horizontal en metros.

Respuesta C. Es una estimación de la precisión de la posición, no una certeza absoluta.

3. ¿Cuándo envía esta práctica las coordenadas a Google Maps?

  1. Al abrir explícitamente el enlace del mapa.
  2. Al escribir el título de la página.
  3. Cada segundo aunque no uses el mapa.

Respuesta A. La aplicación no incrusta ni carga Maps automáticamente. Abrir su enlace comunica la consulta a Google. El proveedor de ubicación del navegador es un servicio distinto.

UNIDAD 5 · CONTENIDO RICO · 25–35 min

Multimedia con alternativas

Los controles nativos ofrecen reproducción sin construir un reproductor desde cero. El contenido debe seguir siendo comprensible cuando no se ve o no se oye.

Objetivos

  • Usar controles nativos y recursos locales.
  • Relacionar track con un archivo WebVTT.
  • Tratar play() como una operación que puede fallar.

El navegador ya incluye un reproductor

audio y video aceptan controls, preload y otras opciones. source permite proponer recursos con su tipo MIME. La compatibilidad depende del contenedor y del códec; la extensión por sí sola no garantiza reproducción. preload es una indicación, no una orden de descarga.

Alternativas equivalentes

track enlaza pistas temporizadas como subtítulos en formato WebVTT. Una transcripción facilita estudiar el contenido fuera del tiempo de reproducción. Para información visual relevante también se necesita una descripción apropiada. Este vídeo es silencioso y dispone de una descripción completa.

Control programado responsable

play() devuelve una promesa que puede rechazarse por políticas de reproducción o problemas del recurso. pause() detiene la reproducción; currentTime y playbackRate permiten observar o modificarla. Iniciar tras una acción del usuario es preferible a depender del autoplay.

Distingue los conceptos

controls crea los controles nativos por HTML. Un botón externo que llama a play() usa JavaScript y la API HTMLMediaElement. Escribir una transcripción no activa por sí mismo una pista de subtítulos.

Ejemplo HTML

<video controls preload="metadata" playsinline>
  <source src="assets/tres-capas.webm" type="video/webm">
  <track kind="captions" src="assets/subtitulos.vtt"
         srclang="es" label="Español" default>
  Tu navegador no puede mostrar este vídeo.
</video>
<p>Descripción: HTML estructura; CSS presenta;
   JavaScript y las APIs aportan comportamiento.</p>

Ejemplo JavaScript

const video = document.querySelector("video");
async function reproducir() {
  try {
    await video.play();
  } catch (error) {
    // Mostrar una alternativa y un mensaje comprensible.
    document.querySelector("#estado").textContent =
      "No se pudo reproducir. Usa los controles o la descripción.";
  }
}
// Enlaza la función al clic de un botón.

Los medios del laboratorio son originales y locales. Algunos navegadores restringen pistas VTT desde file://; en localhost o HTTPS se sirven con su MIME correcto.

Errores que conviene evitar

  • Confiar en autoplay con sonido.
  • Confundir subtítulos con una transcripción completa.
  • Usar únicamente un servicio externo para una práctica que debe funcionar sin conexión.

Reflexión

¿Puede estudiar esta explicación alguien que ha desactivado el sonido o no puede ver el vídeo?

Práctica: Tres capas, tres formas de acceder al contenido

Reproduce un clip local, cambia su velocidad y compara la pista de texto con la descripción. El audio contiene tres notas, no locución.

  1. Reproduce y pausa el vídeo desde ambos tipos de controles.
  2. Activa los subtítulos si tu navegador los ofrece.
  3. Consulta la descripción y escucha las tres notas del audio.

Criterio de logro. El vídeo explica las mismas tres capas que la descripción textual. La pista temporizada sigue cada parte del clip; la descripción permanece disponible. El audio contiene tres notas ascendentes y no aporta información necesaria que falte en el texto.

Autoevaluación

1. ¿Qué activa controls?

  1. Una descarga obligatoria.
  2. Los controles nativos del reproductor.
  3. La cámara del dispositivo.

Respuesta B. controls solicita la interfaz de reproducción del navegador.

2. ¿Qué formato usa esta pista track?

  1. WebVTT.
  2. JSON obligatorio.
  3. Una imagen PNG.

Respuesta A. WebVTT almacena texto con tiempos de inicio y fin.

3. ¿Por qué hay que atender el rechazo de play()?

  1. Porque siempre descarga JavaScript.
  2. Porque todos los vídeos están dañados.
  3. Porque la reproducción puede ser bloqueada o fallar.

Respuesta C. La promesa permite reaccionar ante políticas del navegador, formatos incompatibles o errores del recurso.

UNIDAD 6 · ESTADO LOCAL · 30–40 min

Guardar sin perder el control

Guardar un dato implica decidir qué conservar, cuánto tiempo y con qué ámbito. Esta práctica usa preferencias de estudio y claves identificables.

Objetivos

  • Distinguir la vida de localStorage y sessionStorage.
  • Guardar y recuperar cadenas con claves propias.
  • Gestionar restricciones y borrado selectivo.

Mismo origen, distinto ciclo de vida

localStorage pertenece al origen y puede conservarse entre sesiones. sessionStorage se separa por origen y sesión de pestaña; sobrevive a recargas. Al cerrar la sesión de pestaña normalmente termina, aunque la restauración de sesiones puede recuperarla. Ninguno sustituye a una base de datos compartida.

Un almacén de cadenas

setItem(clave, valor), getItem(clave) y removeItem(clave) trabajan con cadenas. Para objetos se utiliza JSON.stringify y JSON.parse, validando lo recuperado. El usuario, las cuotas o las políticas de privacidad pueden impedir el acceso: utiliza try/catch.

Borrar solo lo que te pertenece

clear() elimina todas las claves del almacén de ese origen, incluidas las de otras prácticas. Esta unidad borra únicamente su clave. No guardes contraseñas, ubicación o información sensible como si este almacenamiento fuera secreto. En file:// su comportamiento no está definido de forma uniforme.

Distingue los conceptos

Persistente no significa permanente. El usuario, el navegador o la navegación privada pueden eliminar o limitar los datos. sessionStorage tampoco se limita a la duración de una carga de página.

Ejemplo HTML

<label for="tema">Tema que quiero repasar</label>
<select id="tema">
  <option value="semantica">Semántica</option>
  <option value="formularios">Formularios</option>
</select>
<button id="guardar">Guardar preferencia</button>
<p id="estado" role="status"></p>

Ejemplo JavaScript

const clave = "mi-curso:tema";
document.querySelector("#guardar").addEventListener("click", () => {
  try {
    localStorage.setItem(clave, document.querySelector("#tema").value);
    document.querySelector("#estado").textContent = "Guardado";
  } catch (error) {
    document.querySelector("#estado").textContent =
      "Este navegador no permite guardar ahora.";
  }
});
// Leer: localStorage.getItem(clave)
// Borrar solo este dato: localStorage.removeItem(clave)

La práctica distingue el dato guardado del valor que está seleccionado en pantalla. Pulsa «Leer» después de cambiar el selector para comprobarlo.

Errores que conviene evitar

  • Usar clear() para borrar una sola preferencia.
  • Esperar que un objeto se guarde sin serializarlo.
  • Suponer que el almacenamiento siempre está disponible.

Reflexión

¿Qué debería mostrar la aplicación si el navegador impide guardar la preferencia?

Práctica: Dos almacenes, dos decisiones

Guarda una preferencia en cada almacén, cambia el selector y lee el dato. Recarga para comprobar que ambos sobreviven a la recarga.

  1. Guarda «Semántica» en localStorage y «En progreso» en sessionStorage.
  2. Cambia los selectores sin guardar y después pulsa Leer.
  3. Borra únicamente la preferencia local y comprueba que la de sesión permanece.

Criterio de logro. Leer devuelve el último valor guardado, aunque el selector haya cambiado. Borrar una clave local no afecta al almacén de sesión ni al progreso del curso. Si falla el acceso, la aplicación informa del problema y no afirma que haya guardado.

  3. Archivos ejecutables.

Respuesta A. Los valores se almacenan como cadenas; los objetos requieren serialización.

  1. Se borra siempre.
  2. Se conserva durante la sesión de esa pestaña.
  3. Se comparte con todos los sitios.

Respuesta B. La recarga no finaliza la sesión de pestaña.

  1. Con clear().
  2. Borrando el historial completo.
  3. Con removeItem(claveDelEjercicio).

UNIDAD 7 · INTERACCIÓN · 30–40 min

Mover también con el teclado

Una interacción visual puede ser útil, pero debe ofrecer otras formas de completar la misma tarea. Clasifica conceptos arrastrando o usando controles nativos.

Objetivos

  • Reconocer dragstart, dragover y drop.
  • Transportar identificadores con dataTransfer.
  • Diseñar una alternativa accesible al arrastre.

Una secuencia de eventos

draggable="true" hace arrastrable un elemento. dragstart prepara los datos; el destino cancela dragover con preventDefault para admitir la operación; drop procesa lo recibido. Estas acciones utilizan la API de arrastrar y soltar.

Datos, no confianza automática

dataTransfer transporta datos en formatos identificados. En esta práctica viaja un identificador de tarjeta, no HTML. El destino solo admite identificadores conocidos y zonas válidas. No insertes sin comprobar texto o marcado recibido del exterior.

La misma tarea por otra vía

Arrastrar puede resultar difícil con teclado, lectores de pantalla o ciertos dispositivos táctiles. Cada tarjeta ofrece un selector de destino y un botón Mover. Ambos caminos actualizan el mismo estado y anuncian el resultado.

Distingue los conceptos

draggable no implementa por sí solo una clasificación completa ni la hace accesible. El comportamiento depende de eventos, datos validados y una alternativa operable.

Ejemplo HTML

<div id="tarjeta-html" draggable="true">button</div>
<section id="destino" aria-label="HTML">
  <h2>HTML</h2>
</section>
<!-- Añade también controles para mover con teclado. -->

Ejemplo JavaScript

const tarjeta = document.querySelector("#tarjeta-html");
const destino = document.querySelector("#destino");
tarjeta.addEventListener("dragstart", (e) => {
  e.dataTransfer.setData("text/plain", tarjeta.id);
});
destino.addEventListener("dragover", (e) => e.preventDefault());
destino.addEventListener("drop", (e) => {
  e.preventDefault();
  const id = e.dataTransfer.getData("text/plain");
  if (id === "tarjeta-html") destino.append(tarjeta);
});

El ejemplo muestra la secuencia mínima. El laboratorio añade validación de identificadores, anuncios y controles alternativos.

Errores que conviene evitar

  • Olvidar preventDefault en dragover.
  • Insertar directamente como HTML los datos recibidos.
  • Ofrecer arrastre como única forma de completar una actividad.

Reflexión

¿Cómo realizarías esta clasificación si no pudieras mantener pulsado el ratón?

Práctica: Clasifica las piezas de una web

Sitúa cada tarjeta en HTML, CSS o JavaScript + API. Puedes arrastrar o elegir un destino y pulsar Mover.

  1. Clasifica las seis tarjetas sin utilizar el arrastre.
  2. Comprueba el resultado y corrige los errores.
  3. Restablece y prueba una tarjeta mediante arrastre, si tu dispositivo lo permite.

Criterio de logro. HTML: button y required. CSS: display: grid y color. JavaScript + API: getCurrentPosition() y localStorage.setItem(). required es un atributo HTML; setItem es un método de una API, llamado con JavaScript.

  2. Para borrar todas las tarjetas.
  3. Para cerrar el navegador.

Respuesta A. El destino necesita admitir la operación de soltar.

UNIDAD 8 · CONCURRENCIA · 35–45 min

Calcular sin bloquear la interfaz

Una tarea intensiva puede impedir que la interfaz responda si ocupa el hilo principal. Un Worker permite ejecutar trabajo en otro contexto y comunicarse por mensajes.

Objetivos

  • Explicar la separación entre Worker e interfaz.
  • Intercambiar progreso y resultados mediante mensajes.
  • Cancelar una tarea y liberar sus recursos.

Otro contexto de ejecución

Un Dedicated Worker ejecuta JavaScript fuera del hilo principal. No accede directamente al DOM: no puede usar document.querySelector para cambiar un botón. No garantiza que toda tarea termine antes; su ventaja es separar el cálculo de la respuesta de la interfaz.

Comunicación explícita

postMessage envía mensajes y el evento message recibe data. Los datos normalmente se copian mediante el algoritmo de clonación estructurada; algunos objetos se pueden transferir. La interfaz presenta el progreso y el resultado que comunica el Worker.

Un ciclo de vida controlado

Crear, iniciar, informar, terminar y liberar. terminate() detiene el Worker desde la página. Si se utiliza un Blob con código propio, revoca su URL al finalizar. Atiende errores y evita iniciar varias tareas cuando solo necesitas una. El código de esta práctica es fijo y no ejecuta entradas del estudiante.

Distingue los conceptos

Un Worker no es una etiqueta HTML ni un temporizador. Ejecuta JavaScript en otro contexto; el hilo principal sigue siendo responsable de la interfaz.

Ejemplo HTML

<button id="iniciar">Calcular</button>
<button id="cancelar">Cancelar</button>
<output id="resultado"></output>
<!-- app.js y worker.js son archivos separados en este ejemplo. -->

Ejemplo JavaScript

// worker.js
self.onmessage = ({ data: limite }) => {
  let suma = 0;
  for (let i = 1; i <= limite; i++) suma += Math.sqrt(i);
  self.postMessage(suma);
};

// app.js (servido desde el mismo origen)
let worker;
document.querySelector("#iniciar").onclick = () => {
  if (worker) worker.terminate();
  worker = new Worker("worker.js");
  worker.onmessage = ({ data }) => {
    document.querySelector("#resultado").textContent = data;
    worker.terminate();
    worker = null;
  };
  worker.onerror = () => {
    document.querySelector("#resultado").textContent = "Error de cálculo";
    worker.terminate(); worker = null;
  };
  worker.postMessage(1000000);
};
document.querySelector("#cancelar").onclick = () => {
  worker?.terminate(); worker = null;
};

El ejemplo didáctico separa dos archivos. Para facilitar el uso local, este laboratorio crea el Worker desde un Blob con código fijo y añade progreso y limpieza de recursos.

Errores que conviene evitar

  • Intentar modificar el DOM dentro del Worker.
  • Confundir concurrencia con una mejora garantizada de tiempo.
  • No cancelar tareas ni liberar URLs de Blob.

Reflexión

¿Qué puede seguir haciendo la interfaz mientras otra parte calcula millones de raíces cuadradas?

Práctica: Un cálculo y una interfaz independiente

Calcula una suma de raíces cuadradas y pulsa el contador durante la tarea. El tiempo depende del equipo y no es una comparación de rendimiento entre navegadores.

  1. Inicia el cálculo y usa el contador de la interfaz.
  2. Prueba la carga mayor y cancela antes de terminar, si da tiempo.
  3. Reinicia y espera el resultado. Observa el progreso.

Criterio de logro. El contador pertenece al hilo principal y continúa respondiendo. El Worker calcula y envía mensajes. Cancelar termina la tarea; no produce un resultado completo. En equipos rápidos puede finalizar antes de pulsar Cancelar: eso no indica un error.

Autoevaluación

1. ¿Puede un Dedicated Worker modificar el DOM directamente?

  1. Sí, con document siempre disponible.
  2. No; debe comunicar el resultado a la página.
  3. Solo si el botón es azul.

Respuesta B. La página recibe el mensaje y actualiza el DOM desde el hilo principal.

2. ¿Cómo se intercambian datos con el Worker?

  1. Con postMessage y eventos message.
  2. Con una etiqueta worker.
  3. Reescribiendo todo el HTML.

Respuesta A. La comunicación se hace mediante mensajes.

3. ¿Qué hace terminate()?

  1. Guarda automáticamente el resultado.
  2. Acelera el cálculo.
  3. Detiene el Worker.

Respuesta C. La terminación detiene la tarea; la página debe actualizar su estado y liberar los recursos asociados.

UNIDAD 9 · HTML ACTUAL · 25–35 min

Interacción nativa, menos código

Los elementos y atributos nativos resuelven patrones habituales de interacción. Elige entre contenido desplegable, un diálogo modal y un panel no modal.

Objetivos

  • Distinguir details, dialog y popover.
  • Probar cierre, foco y teclado.
  • Detectar soporte y ofrecer una alternativa.

details: una revelación en el flujo

details agrupa contenido que se puede desplegar mediante summary. El atributo open refleja el estado abierto. No necesita JavaScript para su interacción básica y mantiene el contenido en el flujo del documento.

dialog: una tarea en primer plano

showModal() abre un dialog modal en la capa superior y hace inerte el resto del documento mientras permanece abierto. Un formulario method="dialog" permite cerrarlo. Proporciona un nombre accesible, un cierre visible y un destino de foco apropiado; comprueba Escape y la vuelta del foco.

popover: información no modal

popover es un atributo global, no una etiqueta. Un botón con popovertarget puede alternar un panel sin JavaScript propio. El modo auto permite cierre ligero, como un clic exterior o Escape. No vuelve inerte el resto de la página. Detecta soporte para conservar una alternativa en navegadores antiguos.

Distingue los conceptos

Un popover no equivale a un diálogo modal. Para una breve ayuda usa un panel; para una decisión que requiere atención exclusiva, considera un diálogo y diseña cuidadosamente el foco.

Ejemplo HTML

<details>
  <summary>Ver una pista</summary>
  <p>Primero identifica el tipo de interacción.</p>
</details>

<button popovertarget="ayuda">Ayuda contextual</button>
<div id="ayuda" popover>
  Soy un panel no modal.
  <button popovertarget="ayuda" popovertargetaction="hide">Cerrar</button>
</div>

<button id="abrir">Abrir diálogo</button>
<dialog id="dialogo" aria-labelledby="titulo">
  <h2 id="titulo">Revisa tu práctica</h2>
  <form method="dialog"><button>Entendido</button></form>
</dialog>

Ejemplo JavaScript

const dialogo = document.querySelector("#dialogo");
document.querySelector("#abrir").addEventListener("click", () => {
  if (typeof dialogo.showModal === "function") dialogo.showModal();
  else document.querySelector("#alternativa").hidden = false;
});
// Detección de popover:
const admitePopover = "showPopover" in HTMLElement.prototype;
// Si no existe, muestra la ayuda como contenido normal.

El ejemplo JavaScript presupone un bloque #alternativa para navegadores sin dialog. El laboratorio incorpora esa alternativa y comprueba popover antes de usarlo.

Errores que conviene evitar

  • Inventar un elemento <popover>.
  • Usar un panel no modal como si bloqueara el resto de la página.
  • Ocultar el cierre o ignorar dónde queda el foco.

Reflexión

¿Cuál de estos tres patrones usarías para una pista opcional que no interrumpa la lectura?

Práctica: Compara tres patrones de interacción

Prueba los controles con teclado. Observa dónde aparece el contenido y si puedes interactuar con el resto de la página.

  1. Abre details con el teclado y observa el flujo de la página.
  2. Abre el diálogo y ciérralo con Escape o el botón.
  3. Abre el popover, pulsa fuera y compara su comportamiento con el diálogo.

Criterio de logro. details despliega contenido en el flujo. showModal abre una interacción modal con el resto del documento inerte. El popover auto flota sin bloquear la página y permite cierre ligero. El foco del diálogo debe volver al control que lo abrió.

Glosario

API
Interfaz que ofrece operaciones y datos a un programa. Las APIs web permiten interactuar con capacidades del navegador.
Contexto seguro
Entorno que el navegador considera confiable, normalmente HTTPS y ciertos orígenes locales como localhost. Algunas APIs lo exigen.
DOM
Representación del documento como objetos que JavaScript puede consultar y modificar.
Evento
Notificación de algo que ha sucedido, como un clic, una entrada o un mensaje recibido.
Foco
Elemento que recibe la interacción del teclado. Debe ser perceptible y recorrer los controles con un orden lógico.
Mejora progresiva
Partir de un contenido útil y añadir capacidades cuando el navegador las admite.
Origen
Combinación de esquema, host y puerto. Delimita muchas operaciones de acceso y almacenamiento.
Permiso
Autorización del usuario y del navegador para acceder a una capacidad. Puede denegarse o revocarse.
Promesa
Objeto que representa el resultado futuro de una operación, que puede resolverse o rechazarse.
Semántica
Significado que aporta el elemento a la estructura y función del contenido.
WebVTT
Formato de texto con marcas temporales para subtítulos y otras pistas.
Worker
Contexto de ejecución de JavaScript separado del hilo principal, comunicado mediante mensajes.
